# RecruitIQ Frontend Interview Guide

## Purpose
Provide a competency-driven frontend interview guide for evaluating candidates building user-facing applications. RecruitIQ AI may generate question suggestions based on missing skills, but panels must score evidence against rubrics.

## Scope
Applies to:

- Frontend roles (React/TypeScript/UI engineering)
- Hiring panels assessing usability, performance, accessibility, and code quality

## Main Content
### 1. Competency model for frontend evaluation
Common competencies:

- component architecture and state management
- performance optimization
- accessibility fundamentals
- testing strategy
- UX reasoning and product thinking

Interviewers map each competency to evidence-based questions.

### 2. Interview structure
A typical loop:

- warm-up: candidate overview of recent frontend work
- core technical: component design and debugging
- practical scenario: performance or accessibility improvement
- collaboration and trade-offs: UX decision-making

### 3. AI-supported question selection
RecruitIQ may suggest questions for missing skills.

Allowed use:

- choose one primary question per missing skill
- select follow-ups to validate depth

Required validation:

- ensure the question targets a rubric competency
- avoid questions that the candidate cannot reasonably address due to missing context

### 4. Question categories (examples)
Architecture:

- “Describe a component design you reused across features. What abstraction did you choose?”

State management:

- “How do you prevent unnecessary re-renders? What patterns do you use?”

Performance:

- “Explain an optimization you shipped and how you measured it.”

Accessibility:

- “Walk through how you ensure keyboard and screen reader usability.”

Testing:

- “What testing layers do you use and what do you trust each layer for?”

### 5. Scoring rubric guidance
Strong candidates show:

- concrete examples tied to shipped outcomes
- explanation of trade-offs and constraints
- correct use of modern frontend patterns
- evidence of testing and quality practices

Score based on correctness, clarity, depth, and trade-off reasoning.

### 6. Human override triggers
Override AI gap conclusions when:

- the candidate demonstrates equivalent experience not captured in resume
- live debugging reveals missing context that AI didn’t capture

## Best Practices
- Ask for reasoning, not only definitions.
- Probe with metrics (“before/after”, user impact).
- Assess accessibility via practical scenarios.

## Examples
### Example scenario: slow page load
Follow-ups:

- “Where did you measure the bottleneck?”
- “What was the change and how did you validate correctness?”

## Summary
This frontend interview guide provides competency categories, recommended structure, evidence-based scoring expectations, and rules for using RecruitIQ AI suggestions as decision-support only.
