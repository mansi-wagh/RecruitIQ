# RecruitIQ Technical Guide: Python (Interview Evidence)

## Purpose
Provide guidance for evaluating Python proficiency during technical interviews. This guide defines competency expectations, evidence to look for, and AI decision-support usage boundaries.

## Scope
Applies to:

- Backend and data-related roles requiring Python
- Interviewers assessing Python fundamentals, quality, and practical application

## Main Content
### 1. Core Python competencies
Interviewers should assess:

- Language fundamentals:
  - data types, control flow, comprehensions
  - exception handling
- Code structure:
  - modular design (functions/classes)
  - readability and separation of concerns
- Data handling:
  - parsing, serialization (JSON), and working with collections
- Testing and reliability:
  - unit tests, edge cases, and failure mode thinking
- Performance reasoning:
  - algorithmic choices and practical complexity awareness

### 2. Evidence-based interview questions
Strong Python candidates can:

- explain why they chose a structure or pattern
- demonstrate correctness verification
- discuss edge cases and failure modes

Example question prompts:

- “Describe a Python module you built. How did you organize responsibilities?”
- “Walk through a bug you diagnosed in Python. What signals did you inspect?”
- “How do you handle input validation and exceptions in an API?”

### 3. Code quality signals
Look for evidence such as:

- clear naming and consistent style
- predictable interfaces and explicit error handling
- tests that cover edge cases
- minimal side effects and maintainable structure

### 4. AI decision-support usage
RecruitIQ AI may suggest missing skill topics.

Allowed use:

- suggest one additional Python competency question
- propose follow-ups based on missing areas

Human control:

- interviewer must confirm the candidate can apply concepts in a scenario
- never treat an AI summary as proof

### 5. Common pitfalls
Interviewers should watch for:

- correct code without explanation of trade-offs
- knowledge limited to syntax without data modeling or reliability practices
- inability to discuss test strategy or edge cases

## Best Practices
- Ask for “before/after” when candidates improved quality.
- Require reasoning, not only definitions.

## Examples
### Example: Exception handling depth
- Candidate explains how they map exceptions to API responses, add logging without leaking sensitive data, and test failure paths.

## Summary
This Python guide focuses on evidence-based evaluation: fundamentals, structure, reliability, and performance reasoning. RecruitIQ AI supports preparation but interviewers retain responsibility for accurate, human-led assessment.
